# ai-sdlc-claudecode 工具质量迭代：CLI 失败传播

## 目标与本轮边界

总目标是验证、修复和迭代 ai-sdlc-claudecode 工具，让真实项目的代码质量结论能够被可靠执行、保存和消费。AiInStock、Linji、ai-product-market 是试点样本来源；业务缺陷数量不是工具完成度，业务默认测试全绿也不能抵扣严格反例。

本轮用户明确选择沿用本地工具，移出额外云端模型派工。本轮交付限定为工具退出语义的一次可复现修复及本地验证；不继续修复 AI Market 的业务代码，不启动额外模型或审查代理。

此前本地 AI Market 结果为默认回归 123/123、换序检查各 12/12，严格业务集 15/22，R1/R2/R4 仍 open。该结果是样本基线，不等于工具正式模型派工、部署或长期效果通过。

## Problem Statement

底层执行器已经报告失败，但 Python 运行入口丢弃了执行结果。`_phase → run → _cmd_run → main` 都没有将非零结果传到进程边界，导致调用方看到退出 0。信号处理也在保存 checkpoint 后以退出 0 结束，可能把中断误作成功。

已实证：在完整 Python CLI 调用链下，本地执行器原生退出 7，修复前 CLI 实际退出 0；SIGINT/SIGTERM 也都实际退出 0。测试使用受控本地执行器和真实子进程/信号，没有模型调用。

比较判断：业务严格用例已经能暴露 7 项失败；当前工具缺陷在向上层调用方传递运行结果这一层。先修退出传播直接消除这一误报通道。新增本地执行引擎、改验收合同或先修 R1 业务都不能替代这个修复。

## Solution

保留已有 RunResult、阶段状态、项目验收合同与 checkpoint 机制，只把真实执行结果贯穿到 Python CLI 的进程退出码。失败保留原生非零码；只有既有 runner 判定完成且执行退出 0，CLI 才退出 0。暂停、等待、部分执行、模拟和证据不足均不得转换为成功。未开始执行就被预算/停滞条件阻止时返回非零。信号终止保存 checkpoint 后保留 128＋signal。

## User Stories

1. 作为 CI/脚本调用方，我需要在工具运行失败时收到非零退出码，避免把失败候选送往后续步骤。
2. 作为运行负责人，我需要区分等待、暂停、证据不足、预算停止与真正完成，以便选择正确的下一动作。
3. 作为问题复现者，我需要中断后保留 checkpoint 和非成功退出码，防止结束状态掩盖未完成工作。
4. 作为工具验证者，我需要用已知坏候选和合法对照走同一个公共 CLI 边界，并如实标注本地受控执行与模型自治的区别。

## Implementation Decisions

- 仅修改 Python CLI 的结果返回链及信号返回值；复用现有 runner 和状态模型，不新增执行抽象或权限开关。
- 不修改验收规则、项目报告、错误学习规则或业务期望，不因为样本有失败而删减必验集合。
- 本地执行器原生非零码原样保留；原生退出 0 但 scope 未完成时按已有语义返回等待 3、暂停/部分/模拟 4、失败/未验证 1；执行前停止 2。
- 子命令的现有读取/报告行为保留正常退出；不因这次修复引入真实模型调用。
- 沿用当前 main 集成分支。其他会话已有的 Bash 中断回归工作不纳入本轮写入或提交范围。

## Testing Decisions

唯一新增验收边界为公开 Python CLI 进程及其持久化 checkpoint。已有 pipeline/候选验收测试继续承接同候选、必验集合与阻断项；不新增重复的业务断言。

| 场景 | 修复前实测 | 目标/验收 |
|---|---|---|
| 本地执行器原生退出 7 | CLI 退出 0，红灯用例已保存 | CLI 退出 7；阶段不 complete |
| 合法完成对照 | 新增受控结果对照 | CLI 退出 0；仅对应阶段 complete |
| 等待/暂停/部分/模拟/未验证 | 状态存在但进程返回链缺失 | 分别保留非零；阶段不 complete |
| 预算在首次执行前耗尽 | 新增未执行对照 | CLI 退出 2；执行器未启动、iteration 为 0 |
| SIGINT/SIGTERM | 两者 CLI 都退出 0，红灯用例已保存 | 分别退出 130/143；checkpoint 和报告存在 |
| 冻结 R1 两项实际失败 | 原本地严格集有两项文件完整性反例 | 用真实 R1 HTTP/SQLite 测试作为本地执行器，CLI 非零，不修改业务来获取绿色 |

R1 的最小样本范围固定为 `test_upload_commit_ack_loss_preserves_committed_file`、`test_storage_collision_then_entropy_failure_preserves_existing_asset`。原断言、失败注入、候选业务字节和原始预期保持不变。它们用于检验工具如何处理失败，不是本轮业务修复任务。

单元与受控 CLI 验证只声称相应协议边界；真实 R1 本地检查只声称本地执行器经 CLI 的失败传播。它们不构成模型自治、完整生产验收或新建本地无模型模式的证明。

## Out of Scope
